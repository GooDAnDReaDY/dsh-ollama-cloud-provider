# DESIGN.md — @goodandready/dsh-ollama-cloud-provider

## Product / Purpose
- **Назначение**: Полнофункциональный Cordis-плагин для DeepSeek Harness (DSH), обеспечивающий интеграцию с облачным API моделей Ollama Cloud.
- **Аудитория**: Пользователи DeepSeek Harness (Web UI и Desktop), использующие модели Ollama Cloud (Llama 3.x, Qwen 2.5, DeepSeek R1/V3, Mistral, Gemma и др.) для чата, reasoning и PTC/tool calling.
- **Статус**: Active (v0.1.37 развернут в production web и desktop профилях, тесты зеленые).

## User Surfaces
- **Web/UI**:
  - `OllamaProviderCardView` — карточка статуса провайдера в каталоге провайдеров DSH (слот настроек).
  - `OllamaSettingsPage` — полноэкранная страница настроек плагина (`/dsh-ollama/settings`) с управлением ключами, правилами ротации, таймаутами и видимостью моделей.
  - `OllamaSidebarQuotaCardView` — компактная карточка квоты/баланса в боковой панели DSH (по умолчанию скрыта: `showSidebarQuota: false`).
  - `OllamaAnalyticsPanel` — аналитическая панель с тепловой картой активности по дням недели и часам, стоимостью токенов и историей запросов.
  - `OllamaUpdateCardView` — карточка проверки и установки обновлений плагина из npm registry.
- **DSH UI / settings / slots**:
  - Слот `settings.plugin.item` для доступа к карточке настроек.
  - Регистрация провайдера `ollama-cloud` в сервисе `@deepseek-ai/dsh-llm`.
- **API**:
  - `GET /dsh-ollama/health` — мониторинг доступности провайдера, количества аккаунтов и доступных моделей.
  - `GET /dsh-ollama/status` — оперативный статус подключения к Ollama Cloud API с задержкой в мс.
  - `GET /dsh-ollama/state` — выгрузка полного состояния каталога и настроек (требует авторизации хоста).
  - `POST /dsh-ollama/config` — сохранение настроек плагина (защищено: loopback + same-origin + CSRF referer).
  - `POST /dsh-ollama/cooldowns/reset` — сброс блокировок/cooldown ключей при исправлении ошибок аутентификации.
  - `POST /dsh-ollama/update` — запуск обновления плагина до доступной версии (только локальный вызов).
- **CLI**:
  - `/ollama models` — список обнаруженных моделей и их контекстных окон.
  - `/ollama rules` — текущие правила привязки моделей к аккаунтам.
  - `/ollama test <model>` — тестовый запрос к указанной модели.
  - `/ollama context <preset>` — переключение пресетов контекста сессии.
  - Интерактивная секция настроек в DSH TUI (`tui-settings.ts`).
- **Документация**:
  - `README.md`, `README.ru.md`, `README.zh.md`, `CHANGELOG.md`, `index.md`, `docs/design/DESIGN.md`, `docs/deployment/DEPLOYMENT.md`.

## Visual Direction
- **Атмосфера**: Нативный компонент DeepSeek Harness, строго следующий системной теме оформления DSH (dark/light).
- **Утверждённые референсы и что из них берём**:
  - DSH design system: переменные CSS темы (`var(--bg-primary)`, `var(--bg-secondary)`, `var(--text-primary)`, `var(--text-secondary)`, `var(--border)`, `var(--accent)`).
  - Иконки DSH: SVG-иконки с обязательным маркером `data-dsh-plugin`.
- **Не копировать**:
  - Сторонние стили, Tailwind без изоляции, инлайновые нетемизированные цвета (`#ffffff`, `#000000` в клиентском коде запрещены).

## Foundations
- **Цвета и роли**: Все цвета разрешаются через системные переменные DSH host webview.
- **Типографика**: Нативные шрифты платформы DSH (`system-ui`, `-apple-system`, `sans-serif`), моноширинные для логов и ID.
- **Сетка, отступы, responsive**: Grid/flex с шагом 4px/8px/12px/16px, полная адаптивность для окон DSH Desktop и мобильного интерфейса через dsh-lanmode.
- **Accessibility**: ARIA-атрибуты для интерактивных кнопок, цветовой контраст WCAG AA, поддержка экранных дикторов.

## Components And States
- **Компоненты**:
  - Переключатели видимости моделей (All / Selected / Custom).
  - Таблица аккаунтов с маскированными ключами и индикатором cooldown.
  - Тепловая карта запросов (Heatmap) с локализованными днями недели (en, ru, zh).
  - Индикатор доступности обновления с кнопкой «Обновить» и индикатором прогресса.
- **Loading / empty / error / success**:
  - Skeleton/spinner при загрузке каталога моделей и проверке обновлений.
  - Понятные сообщения при отсутствии настроенных ключей («Добавьте API-ключ в настройках»).
  - Баннер ошибки при отказе API с возможностью сброса cooldown.
- **Формы, валидация и действия**:
  - Валидация формата API-ключа (непустая строка, маскирование при отображении).
  - Защита write-маршрутов fail-closed.

## User Flows
- **Критические сценарии**:
  1. Первичная настройка: пользователь открывает настройки -> вводит API-ключ Ollama Cloud -> плагин опрашивает каталог моделей -> модели появляются в общем селекторе DSH.
  2. Выполнение запроса с PTC (Tool Calling): DSH отправляет запрос -> плагин генерирует глобально уникальный `call_uuid` -> агент выполняет шаги без конфликта ID в логе сессии.
  3. Исчерпание квоты: плагин автоматически переключается на запасной аккаунт до отправки первого чанка клиенту; если все ключи заблокированы — возвращается структурированная ошибка с предложением сброса.

## Do / Don't
- **Do**:
  - Проверять метод запроса и источник вызова на всех маршрутах изменений.
  - Логировать подавленные сетевые сбои через `bestEffortFailed`.
  - Генерировать глобально уникальные tool-call ID при отсутствии upstream ID.
- **Don't**:
  - Не использовать тихие `.catch(() => {})`.
  - Не включать `showSidebarQuota` по умолчанию (только по явному выбору пользователя).
  - Не сохранять артефакты `.tgz` в корневом каталоге checkout.

## Locked Design Decisions
- **2026-10-21** — Ротация аккаунтов до первого потокового токена; переключение на лету невозможно после начала стриминга.
- **2026-11-06** — `showSidebarQuota: false` по умолчанию; карточка в боковой панели включается только в настройках.
- **2026-11-10** — Защита write-маршрутов требует совпадения origin и loopback сокета для предотвращения CSRF/DNS rebinding.
- **2026-11-11** — Tool-call ID генерируются через `randomUUID` (`call_${uuid}`), предотвращая коллизии `subCallId` в сессиях DSH.
